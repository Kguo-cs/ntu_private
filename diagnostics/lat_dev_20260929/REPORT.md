# lat_dev_jsd 专项诊断

日期：2026-09-29。已重新读取修改后的工作树：噪声 Hungarian 已注释、训练 batch=512、LR=1e-4、每8个 epoch验证、任务名为 `xflow512_l1_v1_nomatch_nocol32ego`，从 AIRL 权重初始化。旧 matching 缺陷不再作为当前活动代码的原因。以下只有诊断和推理实验，没有修改训练代码或权重。

**结论：本地已训练 last.ckpt 的生成距离分布确实比 GT 宽；增加采样步数改善很小。最值得优先验证的是中心线几何被稀疏采样并压缩进冻结的路沿表示，以及学习率仍过早衰减。指标公式与官方一致，但它只统计距车道点1.5m以内的车辆，需要同时看阈值内比例。**

新 nomatch 实验尚无本地可用曲线；不能把旧 last.ckpt 的探针结果冒充新训练结果，也无法仅凭现有日志确认用户观察的平台持续了多少 epoch。

## 1. 已训练 checkpoint 的实际生成结果

加载 `src/waymo_data/last.ckpt`（epoch=87，global_step=84832），encoder 权重加载的 missing/unexpected keys 均为空。固定 seed=817，随机抽128个验证场景，合计908辆车；固定同一初始噪声，比较不同采样步数。预测与同批 GT 比较，使用与项目完全相同的 `JSD = jensenshannon(...)² × 10`，已逐项核验一致。

| 模式 | lat_dev_jsd ↓ | 距车道点≤1.5m的车辆比例 ↑ | 阈值内平均距离 |
|---|---:|---:|---:|
| GT | 0 | 99.23% | 0.335m |
| 10步 | 1.1992 | 81.28% | 0.692m |
| 20步 | 1.1674 | 79.63% | 0.682m |
| 50步 | 1.1322 | 79.63% | 0.680m |
| 10步，末次模型调用改至 t=.05 | 1.1888 | 81.39% | 0.693m |

生成结果在0.5–1.5m区间明显比 GT 多，GT 的主峰集中于0.1–0.4m。不是一个仅增加积分步数就明显改善的问题。50步的略低 JSD 也伴随更少车辆进入统计阈值，不能称整体几何质量更好。

排除 Ego 后，10/20/50步的 JSD 分别为1.6936/1.6428/1.6017，说明固定真实 Ego 会稀释生成车辆的分布差异。

在GT附近加噪后直接去噪，t=.05时非Ego车辆位置误差均值0.580m；t=.1时1.190m。这是特定噪声构造下的恢复误差，不是最终生成与逐车GT匹配的误差，也不能直接推算某个根因贡献。

## 2. 与 lat_dev 最直接相关的地图信息瓶颈

### 中心线采样过稀

`src/smart/utils/preprocess.py:157-160`：非road-edge片段保留 `[::10]`，road-edge保留 `[::2]`。原始按5m切片；合成100m直线验证，中心线仅保留 `[0,5]`、`[50,55]` 两段，路沿则约每10m保留5m。

沿程45m范围的中心线几何没有以原始片段形式输入。直路可以靠方向外推，但弯道、交叉口和车道变化不一定能恢复。评估却使用完整SD中心线经100点重采样后的几何。

### 去噪器的显式地图节点仅为道路边缘

`src/smart/modules/map_decoder.py:90`、`:154-179` 只输出类型4/5（road edge），中心线0–3只参与先前的map-to-map聚合。`smart_decoder.py:115` 当前 `sep_map=False`；`smart.py:208` 在finetune中冻结map encoder。

**并不是完全没有中心线信息。** 实际256场景、1764辆GT车的检查中，99.9455%的FOV内中心线anchor可以传到某个路沿节点；所有GT车在当前邻居范围内，都能经两跳接触至少一个中心线anchor。但是信息经过稀疏采样及冻结embedding压缩，去噪器没有直接密集中心线坐标。

GT车可访问的最近中心线anchor距离中位数为5.72m、P90为13.73m。这些是anchor间距，不是完整曲线的误差，不能说车道几何一定错了5.72m；它说明模型需要从较远且间接的锚点恢复精细距离。

### 精确局部几何被丢弃

`token_processor.py:640` 缓存了 `traj_pos_local`，但读取缓存时 `:848-849` 没加载它，map decoder只使用 `token_idx` 对应码本形状。

32个训练场景、21266个token重新计算argmin，缓存index与当前码本 **0个不一致**，排除码本版本错配。常规近5m直片段精度较好：中心线局部横向重构误差P95为0.0435m；但端点弦长≤4.9m的短/强弯片段中，中心线47.15%、路沿71.29%的片段误差超过0.1m。这个误差只针对已保存的局部三点和码本对应点，不是整条道路的几何误差。

**建议的地图消融顺序**：先保持同一数据，只让现存中心线节点也直接进入denoiser；再用独立版本缓存提高中心线采样密度；随后尝试解冻地图编码器或保留精确局部几何残差。分步比较，避免同时改完无法定位贡献。应保留旧SMART非SD路径的行为，并为SD路径单独配置。

证据：`map_geometry_stats.json`、`map_token_verify.json`；复现脚本为 `map_geometry_audit.py`、`map_token_verify.py`。两跳覆盖使用CPU cKDTree模拟近邻，精确等距离点的选择顺序可能与torch_cluster不同，不影响它作为覆盖性诊断的用途。

## 3. 当前仍存在的优化瓶颈

### 学习率仍在第128次更新衰减完

`configs/model/smart.yaml:5` 仍为 `lr_total_steps: ${trainer.max_epochs}`，`smart_gail.py:785` 仍为 `interval: step`。因此新配置的 `1e-4` 会在第128次更新降至 **5e-6**。单卡、batch512、493542文件，每轮约964次更新；精细位置拟合的大部分训练将使用最低LR。

应统一调度单位，使用真实optimizer总更新次数，或将epoch调度语义贯彻到底。这个确定配置问题应先修，才能公平比较地图设计。

### XY的位置监督弱，且没有按normal_scale归一化

`diffusion_utils.py:435-438` 权重：position=.02，heading=.1，shape=.04，velocity=.2。调用当前真实loss，在同等非零单位误差下，速度输出梯度是位置的10倍；将normal_scale从1改为100，确定性loss不变。

这只是输出坐标梯度比，不等于网络参数梯度一定相差10倍；不同属性单位也不同。它表明当前训练没有专门强调车道横向的精细误差，normalizer不能替代loss归一化。

建议记录各分量loss及共享层梯度，先把位置权重提高2–5倍做单变量实验；进一步可监督相对于GT邻近车道的横向残差，或匹配生成/真实距离分布。不要只加入“距离中心线越小越好”的惩罚，因为GT分布本身不在0处。

### 采样和L1目标是次级消融

当前10步Euler最后调用t=.1，再得到最终预测；20步最后调用t=.05。`t_eps=.05` 会影响更密步长的最后更新，40/64步末次更新只分别走向pred_x0的50%/31.25%，所以不能盲目认为越多步越精确。本次真实checkpoint对比也显示收益很小。

当前x0使用L1。对于多模态条件分布，L1最优解偏向条件中位数，L2对应条件均值；它们的Flow输运不保证相同。分析性双模态例子显示L1可能改变模式比例，但没有证明这就是该模型lat平台的原因。可以在地图和scheduler对齐后比较L1/L2，避免把这个理论风险当成已证实主因。

输出local/global坐标往返测试最大误差4.77e-7m，未发现旋转方向错误。

证据：`loss_sampling_checks.json`、`loss_sampling_checks.py`。

## 4. lat_dev_jsd到底在比较什么

`old_gen_metrics.py:732`、`:755`、`:949` 与官方实现对32个场景逐值完全一致：

1. 计算车中心到车道上100个重采样点的最小欧氏距离；它包括离散采样间距带来的沿程距离，并非纯连续曲线法向距离。
2. 删除距离超过1.5m的车辆。
3. 对剩余车辆以0.1m分箱，比较概率分布，最后乘10。

所以它既不直接衡量所有车辆的越界率，也不是平均横向误差。GT自比为0，没有天然非零平台。

512个参考场景、3852辆车的敏感性实验：

| 对GT执行的操作 | 与原GT的lat JSD |
|---|---:|
| 原样 | 0 |
| 沿最近车道法向移动0.05m | 0.00585 |
| 移动0.10m | 0.02271 |
| 移动0.20m | 0.06348 |
| 移动0.50m | 1.04149 |
| 全部吸附到连续车道线 | 1.91187 |
| 全部吸附到离散车道点 | 5.26818 |

这些敏感性数值依赖抽样与操作，不能直接换算模型的真实位移误差。它们说明“越贴中线越好”并不等于JSD更低。

另外，复制GT两份，把其中一份全部移出地图：阈值内比例由99.66%降到49.83%，lat JSD仍然为0。必须同时记录：阈值内比例、全部车距离P50/P90、15档生成/GT直方图。建议额外分开报告Ego和非Ego。

本地可见的旧约0.88曲线仅记录epoch0、step0–6，来自旧AIRL初始化实验的单batch验证，不能用来证明新nomatch模型或已训练last.ckpt长期不收敛。当前专项使用的是实际已训last的独立推理证据。

证据：`metric_sensitivity.json`、`metric_sensitivity.py`。

## 5. 推荐下一轮实验

- **先修scheduler并确认曲线单位**，保存真正的训练epoch/global_step和真实SD指标。
- **首要建模实验：中心线直接作为denoiser的地图条件**；与当前road-edge输出保持相同初始化、更新次数、种子、评估集。
- 随后分别比较中心线加密、地图编码器解冻、位置loss提高、L2目标。避免一次改多个变量。
- 评估固定matched场景集合，同时看lat JSD与1.5m内比例。最终再跑完整50k，不依据128场景小样本的微小变化选模型。

复现脚本使用本机sim环境、固定本机仓库路径，前三个诊断脚本输出到 `/tmp/sim_lat_audit`，两个map脚本输出到脚本所在目录；`checkpoint_probe.py`为CUDA推理，其余诊断主要为CPU。全部只读取训练数据和权重。本次没有执行重训消融，因此地图和loss因素的因果贡献尚未定量。
